Issue 分析

/api/issue-analysis ❓ 使用说明 🔗 AceHarness 仓库
🔗 粘贴 Issue URL（GitCode / GitHub / Gitee），点「开始分析」——AI 自动完成问题定位、根因分析、修复建议。
📄 产出六大章节报告：问题概述、环境信息、复现步骤、根因结论、修复建议、验证建议；点击历史任务进入独立详情页阅读，可下载 Markdown。
💬 与 Agent 交互：分析中可点「Issue分析详情」进 AceHarness 工作台——查看实时进度、补充信息给 Agent、处理人工审批。
🔑 私有 Issue需在提交时填 Access Token；优先级/类型可不填（自动判断）。
🔒 身份隔离：需登录后提交；分析历史按账号隔离，只能看到自己提交的任务。
点击任务进入独立详情页，查看完整报告、诊断时间线、证据和修复补丁。

PR 监控

/api/pr-review/runs ❓ 使用说明 🔗 AceHarness 仓库
🔹 组织 PR：默认展示 CPF-Flutter 下全部作者、全部代码仓库的 PR；可按状态、仓库和标题/描述筛选，并分页浏览。
🎛 人工监控：PR 作者本人或管理员可以从组织 PR 列表启动监控；Webhook 消息不会自动启动监控。
🔑 令牌：点「🔑 令牌」配置 GitCode 个人访问令牌后，监控工作流将以你的身份访问 GitCode（读 diff / 门禁 / 回写评论）。
🔒 身份隔离：监控任务按 AceHarness 账号隔离，只能看到自己启动的任务。
🔄 实时状态：监控阶段、步骤进度、人工审批提醒、最终评审结论、步骤输出文件，每 10 秒自动刷新，也可点 ↻ 立即刷新。
