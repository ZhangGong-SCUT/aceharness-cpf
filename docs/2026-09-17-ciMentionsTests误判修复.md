# 2026-09-17 ciMentionsTests 误判修复——只看最新一轮构建开始评论

## 时间

2026-09-17 11:25 ~ 12:20(本地)

## 解决了什么问题

### 问题(用户反馈,PR #1536/#1537)

flutter_engine PR1536/1537 的 CI 门禁**只含静态检查+代码编译**
(engine 仓门禁不含测试,CI 已发「代码门禁通过」),四项 label 全绿,
但监控平台一直显示"监控中"不收口。

根因(上一提交引入的回归):`ciMentionsTests` 扫描**全部历史评论**,
只要任何评论里出现「门禁/构建」+「测试」字样就认为本轮门禁含测试——
而 PR 的历史「代码门禁通过」报告正文、旧轮次构建评论里带「测试」字样,
导致纯编译门禁被误判「冒烟测试还在跑」→ running 永不收口。

### 方案

`ciMentionsTests` 改为**只看最新一条「门禁构建开始」CI 评论**:

- 按 created_at 排序,取最后一条 isCiBot 且匹配
  「门禁构建开始|开始构建|已触发构建」的评论
- 该评论含「测试」→ 本轮门禁含测试(测试是五项之一,无终态不收口)
- 不含 → 纯编译门禁,四绿即 green

### 验证

- vitest 45/45(+1 回归用例:历史评论含测试、最新构建开始评论纯编译
  → green;复刻 pr1536 真实评论序列)
- pr1536 真实数据:engine 仓全部 9 轮「构建开始」评论均为
  「包含静态检查、代码编译」,修复后判定 green ✓
- pr1958 数据不受影响:其「构建开始」评论含「代码编译和测试」→
  测试无终态时仍正确 running ✓
- 现场处置:force-transition 唤醒 1536/1537 挂起 run 重查门禁,
  两者均判 green,正在走分流链收口(识别→等待门禁→分类处置→…→完成)
