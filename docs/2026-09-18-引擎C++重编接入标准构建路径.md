## 解决了什么问题

**问题**：issue#2646 迭代修复中，用户明确"接受引擎重编"，工作流修改了引擎 C++ 代码（platform_view_ohos_napi.cpp）却**没有编译**，验证结论只含糊写"未执行（环境性）：引擎重编"——既没按标准路径尝试，也没说清缺什么，最终 run failed（engine_aligned=false）。

**方案**：按官方构建指南（flutter_samples/docs/ohos/getting-started/flutter-oh-engine-build-guide.md）落地三层：

| 层 | 内容 |
|----|------|
| ① references/engine-build.md | 指南全文入 skill（含来源链接+工作流适配说明），修复验证时 MANDATORY 读 |
| ② scripts/build-engine.mjs | 按指南编排：环境探测（JDK17+/Python 3.8–3.11/ninja/depot_tools/源码同步状态/DEPS_ohos allowed_hosts 逐域网络/磁盘 50G+）→ `cp ohos.gclient + gclient sync` → `./ohos -t <mode>` → 产物校验（src/out/ohos_\<mode\>_arm64/{libflutter.so, flutter.har}）。`--check-only` 仅探测；已同步的树网络不可达不阻断重编 |
| ③ 两个诊断工作流修复验证步骤 | 【引擎 C++ 重编】条款：改了 engine/src 必须重编才算 engine_aligned=true；先探测，满足走全流程，缺失则 missing 列表原样进 step-conclusion——**禁止不探测就写"环境性未执行"** |
