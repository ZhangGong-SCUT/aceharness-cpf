# dev 分支 SDK 对齐修复（Issue 诊断工作流）

**时间**：2026-09-16 08:00 ~ 09:35
**背景**：Issue #2721（flutter_flutter 仓 `dev` 分支）的诊断 run 因 `matched=false`（无对应 SDK）→ `engine_aligned=false` → 真机验证被规则禁止 → `conditional_pass` 落 failed。同环境同配置下 #2492（`oh-3.41.9-dev` 分支）已能拿到 complete，证明问题定位在 dev 分支的 SDK 对号入座。

## 问题 → 方案 → 验证

### 1. dev 分支无版本号，匹配不到 SDK

- **问题**：`resolve-ohos-flutter-sdk` 的 `versionHint("dev")` 为 null，五套已登记 SDK 的 aliases 均不含 `dev`，score=0 → `matched=false`（reason：禁止用日常 SDK 凑真机）。
- **方案**：查证 `dev` 是 CPF-Flutter 主线（领先 `oh-3.44.9-dev` 1072 commits，版本系列上 3.44.9 最新），在 `configs/ohos-flutter-sdks.yaml` 的 `3.44.9-ohos` 条目 aliases 增加 `dev`。**注意引擎读的是运行时副本 `~/.aceharness/configs/`，两份都要同步**（本次踩坑：只改仓库份不生效）。
- **验证**：`resolve-ohos-flutter-sdk.mjs --branch dev` → `matched: true, sdkId: 3.44.9-ohos`；新 run 的 `ohos-flutter-sdk.json` 更新为 matched。

### 2. detached HEAD 读不到分支名

- **问题**：诊断流程 clone 后 checkout 到目标 commit，`.git/HEAD` 是裸 hash（非 `ref: refs/heads/x`）；采集 JSON 的 branch 字段又是 LLM 输出（有时不填）→ 双通道皆空 → `branch: null` → "没有 repo 分支，无法对号入座"。
- **方案**：`readRepoBranchFromDisk`（TS 引擎侧 + mjs 脚本侧同步）增加 detached HEAD 兜底链：① `.git/refs/remotes/origin/HEAD` 的 symbolic ref（clone 默认分支）→ ② `packed-refs` 中 hash 匹配的 `refs/remotes/origin/<branch>`（优先 dev/master/main）→ ③ `refs/heads/` 唯一本地分支且 hash 一致。
- **验证**：构造 detached 测试仓（HEAD=裸 hash + origin/HEAD→dev）跑 mjs 脚本 → `branch: dev, matched: true`；真实 run 中 branch 成功读出。

### 3. flutterBin 在 Linux 返回 .bat 路径

- **问题**：`flutterExecutable` 无条件优先 `flutter.bat`（Windows 惯性），Linux SDK 目录同时含两文件时引擎 pin 出 `/bin/flutter.bat`，agent 需自行纠正（#2492 靠 agent 自救未翻车）。
- **方案**：TS + mjs 两处按 `process.platform !== 'win32'` 优先 POSIX 路径。
- **验证**：新 run pin 文件 `flutterBin: /home/flutter/flutter-sdks/3.44.9-ohos/bin/flutter`（无 .bat）。

### 4. 引擎热更新链

- TS 侧修改经 `next build` 后需重启引擎（`PORT=3031 node --max-old-space-size=8192 server.js start`；默认 3000 会撞 AIWeb 后端端口）。
- `ohos-flutter-sdks.yaml` 由 `loadOhosFlutterSdkInventory` 每次 resolve 实时读取，改完即时生效无需重启。
- run 中途修复 SDK pin 可行：`refreshOhosFlutterSdkPin` 的触发条件含 `branch && !matched`，下一个步骤状态转换时自动重算。
