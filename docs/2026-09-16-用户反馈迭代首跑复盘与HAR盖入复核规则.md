### 发现的问题

1. **HAR 基线管理靠运气（结构性，本次修复）**：AI 轮把修复版 HAR 盖进 3.44.9-ohos SDK cache 后未还原；迭代轮 verifier 盖入本轮 HAR 后**无 md5 复核**——若盖入失败会静默用 AI 版代码构建，而 AI 版同样能过黄金标志，将得出「用户方案有效」的假结论。本次靠 agent 自觉核对 oh_modules 才过关。
2. 第一次迭代 run 启动即失败（run-1789551765583，"引擎运行前校验未通过"，无产物；原因待查，用户重试成功）。
3. 修复验证 step 输出仅 3 行 JSON，过程细节未沉淀 outputs（证据在会话命令流里）。
4. 装载阶段复制的 ohos-flutter-sdk.json 带错误 branch（oh-3.35.7-release，实际 oh-3.44.9-dev），靠 verifier 手动纠偏。

## 修复：盖 HAR 三步 + md5 强制复核（四处落地）

规则内容：**备份旧 cache（留指纹）→ cp 新 HAR → md5sum 复核 cache == 本轮 outputs HAR；不一致或跳过 = verdict=fail 禁止构建**。构建后另核 oh_modules 实际源码含本轮修改。
