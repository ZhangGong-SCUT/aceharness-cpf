# 2026-09-17 PR 门禁误判 green 修复——冒烟测试无终态时禁止提前收口

## 时间

2026-09-17 10:15 ~ 10:35(本地)

## 解决了什么问题

### 问题(用户反馈,PR #1958)

PR 监控平台"步骤进度:完成",但 GitCode 门禁"冒烟测试"还没出结果
(DCO/静态/编译/AI 四绿,测试 pending),监控任务却已收口——
收口后无人盯,测试若后续失败也不会被 Webhook 唤醒处理
(唤醒只对 running/preparing 状态生效,completed 不在名单)。

根因(ohos-pr-gates.mjs classifyOhosPrGates 分支顺序缺陷):

```js
} else if (dcoOk && staticOk && compileOk && !testFail) {  // 测试只要求「没失败」
    phase = 'green';   // 测试 pending 也判绿
}
// 「编译已过,测试还在跑 → running」的分支排在后面,永远轮不到
```

工作流被 CI 评论唤醒后重查门禁,测试 pending 被判 green →
就绪 → 完成,监控使命提前结束。

### 方案

1. 新增 `ciMentionsTests(comments)`:识别 CI 门禁评论中
   「门禁/构建…测试…」字样(= 本轮构建含测试任务,测试是门禁一部分)
2. green 分支增加约束:**测试未通过(testOk=false)且 CI 提及测试 →
   running**("含测试的门禁须五项全绿才算完成,继续等,不要提前收口")
   - 测试成功 → green(五项全绿)
   - CI 不提测试(纯编译门禁的仓库/流程)→ 四绿仍 green(不误伤)
3. 回归测试 +3(#1958 形态 running / 五绿 green / 纯编译四绿 green)
