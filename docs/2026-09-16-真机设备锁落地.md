# 2026-09-16 真机设备锁落地——多 run 并发防抢占

## 时间

2026-09-16 14:30 ~ 15:00(本地)

## 解决了什么问题

### 问题

用户疑问:多个 Issue 同时启动分析,只有一台真机,会不会抢占?

核查结论:**会,且此前无任何保护**:

1. 引擎侧 `src/lib/workflow/device-lock.ts` 实现了完整锁机制,
   但**全代码库零调用(死代码)**
2. 技能文档无设备锁指令
3. #2721 run 里 agent 自述「获取/释放设备锁」为幻觉——stream 中无任何
   实际锁命令(搜到的 "lock" 均为 ohpm lock.json5)
4. CPF-AIWeb `MAX_CONCURRENT_ISSUEANALYSIS_TASKS=3` 允许 3 个 run 并发,
   同时到达真机阶段时:`hdc install -r` 互相覆盖(同 bundleName demo)、
   hilog 整机抓取串台、`uitest` 点击/`snapshot_display` 截图串场

### 方案

**技能级强制约定**(不依赖引擎改造,agent 可直接执行):

1. 新增 `skills/cpf-ohos-issue-analysis/scripts/device-lock.mjs`:
   - 子命令 acquire(阻塞等待,默认 30min,5s 轮询,超时 exit=3)/
     release(仅持有者)/ status / clean
   - 锁文件 `~/.aceharness/data/device-locks/{deviceId}.lock`,
     与引擎 device-lock.ts 同目录同格式(将来引擎启用可互认)
   - 租约 45 分钟(覆盖一次复现/验证窗口);同 run 重入 = 续租
   - 僵尸锁判定:runId 在 `~/.aceharness/runs/` 无归档目录 **且锁龄 >5min**
     (保护窗防止新 run 归档未建时被误抢);崩溃后 45min 自动过期
   - 按设备序列号独立加锁,天然支持多台设备
2. 技能文档强制规则:
   - common-experience.md 通用经验 +1 条(第 11 条:真机操作先拿锁,
     完事释放,超时降级 needs_runtime_validation)
   - NEVER 列表 +1 条(不持锁禁操真机;只读查询 hdc list/param get 不需锁)
   - fix-strategy.md 验证要点 +第 0 条(真机复测全程持锁,无锁结论
     verifier 应降 conditional_pass)

### 验证结果

脚本全链路实测(A=run-test-a,B=run-test-b,设备 TEST-DEV):
- A acquire → 成功
- B acquire --wait 8 → 等待 10s 超时,exit=3,返回 holder 信息
- A release → 成功
- B acquire → 立即成功;B release;status → 空闲
- 误抢保护:锁龄 <5min 时不因 run 目录缺失判僵尸(修复前 B 会误抢 A 的锁)

skills 目录硬链接同 inode(3145978),运行时即时生效,下次诊断 run 起
agent 将按 NEVER 规则持锁操作真机。
