## 问题与方案

- 限流同时存在编译/静态/测试失败时仍进入修复：有效限流优先于自动处理分支；识别“限制提交”和“触发门禁次数已达到上限”两类 CI 评论。后续实际接受构建事件解除旧限流；最新尝试拒绝/接受与历史接受次数分开。人工指令/建议等待覆盖不得绕过限流。发送 start build 前重新拉取评论，限流或读取失败时不发送；使用本机模拟服务测试，无远端写入。
- 空/缺失产物被标为归档完整：要求非空证据或调用方显式允许空清单；归档必需产物来自已执行步骤及门禁来源，保留上次清单的必需项。源已清理时只接受与上次清单 hash 一致的归档；partial 与 failed 都不能通过终止步骤。

- 路径校验失败后仍写 manifest：源、目标、根路径和祖先路径统一拒绝符号链接；根校验失败立即返回。以普通文件内容进行哈希和复制，临时文件原子发布，快照独占发布，回读校验。此处没有宣称能抵御同 UID 恶意进程并发替换父目录。
