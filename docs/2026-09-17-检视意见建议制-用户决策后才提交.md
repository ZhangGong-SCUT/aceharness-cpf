# 2026-09-17 AI 检视意见建议制：生成不推送，用户决策后才提交

## 时间
2026-09-17 19:40 ~ 22:00

## 解决了什么问题

**问题**：工作流把 AI 检视意见自动修复并推送，然后才让用户审核（先斩后奏）。用户认为 AI 意见有时不合适，不应该不由分说就改就推；而门禁类问题（静态/编译/DCO）才是必须修的。

**方案**：检视意见改「建议制」——AI 按意见生成建议修复（fix.patch + review-suggestion.json）**不推送**，run 挂起等用户在面板决策：
- **应用**：以 `user_apply_patch` 指令启动新 run 推送（用户已确认）
- **驳回**：以 PR 作者身份发【AI检视处理】标记评论（后续 run 识别后不再生成建议）→ 停监控
- **反馈**：原有「按我的想法改」通道（用户指令 = 自动推送合理）
- **门禁类不动**：静态/编译/DCO 仍自动修自动推

### 实施要点

| 层 | 改动 |
|----|------|
| 工作流 yaml | 模式A生成建议产物；judge conditional_pass→挂起（删自循环重试）；挂起/分流检视/等待门禁任务识别建议模式短路（防唤醒空转烧 token） |
| check-pr-gates.mjs | review_pending_decision 检测（建议+head 未变→挂起等决策；漂移→正常流程）；user_apply_patch 纳入 user_fix 覆盖；块样式/-和>-双匹配；isDirectRun 符号链接修复 |
| fetch-ai-review.mjs | 驳回标记识别：标记晚于全部待处理意见→dismissed（驳回后新意见不受影响） |
| 路由表 | 分类处置/分流检视 + review_pending_decision→挂起 |
| AIWeb 后端 | 决策路由 apply/dismiss；apply 含基线漂移校验；dismiss 发标记评论（作者→决策用户令牌链）+停监控+防重；getReviewFixData 暴露 suggestionMode（建议 patch 不写持久化） |
| AIWeb 前端 | 建议模式面板：横幅+三按钮（应用/驳回/反馈）+确认弹窗+漂移警告+applied/dismissed 结果态 |
