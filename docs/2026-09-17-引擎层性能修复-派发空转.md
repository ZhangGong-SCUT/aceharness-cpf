# 2026-09-17 引擎层性能修复：消除步骤派发空转

## 时间
2026-09-17 16:00 ~ 17:10

## 解决了什么问题

**问题**：5 个 PR 监控同时启动时，每个步骤从派发（step-start）到 LLM 开始产出要空转 100~520 秒，而单步 LLM 实际工作仅 25~100 秒。用户感知"半小时才走几步"。

### 诊断过程（全部数据实证，零猜测）

1. **事件库时序分析**（workflow-events.sqlite）：全部 5 run 的每个 step-start→首 chunk 间隔 100~520s；单跑时段仅 13~46s → 空转与并发数正相关
2. **会话库解剖**（opencode.db）：LLM 单轮中位 5.9s（快）；会话在首 chunk 前仅 14s 才创建 → 引擎迟迟没发 prompt
3. **基础设施逐一实测排除**：serve API 8~26ms、网关 4 并发 3.4s、per-run 锁独立（registry.ts 注释明确并行设计）
4. **四点打点**（本次新增）后实跑定位：`mcp-ensured +61,258ms` —— **MCP ensure 一项占满 60 秒**
5. **直连复现**：`mcp/connect` 固定 30.017s（已连接状态同样），status 显示 `failed: Operation timed out after 30000ms`——vision-look 每次连不上，引擎每次 execute 都重试

### 三个根因与修复

| # | 根因 | 修复 | 效果 |
|---|------|------|------|
| ① | 共享 serve 全局单例+指纹切换，不同用户 run 交替触发杀 serve 冷启；cleanup() 空闲时也杀 serve | `ensureServer` 改 userId→常驻 serve 池（2h 闲置回收，会话跨 serve 可恢复）；cleanup 不再回收 | serve 复用 1ms；无指纹重启 |
| ② | **MCP 每次 execute 都 add+connect**，connect 固定 ~30s 超时（60.2s/步的真凶） | 每个 serve client 同名服务器只连接一次（WeakMap 记录） | mcp-ensured 61,258ms → 2ms |
| ③ | 无可观测性，问题定位要靠考古 | 九点 [StepTiming] 打点：step-start/context-done/engine-enter/server-ready/mcp-ensured/agent-registered/vision-registered/session-created/prompt-sent | 问题秒级可见 |

另：`.engine.json` driver stdio→sdk，引擎统一走 HTTP wrapper（消除 `opencode acp` 子进程冷启动），实测 acp 进程数 0。

### 验证

- **实跑**（issue #2731 诊断工作流，信息采集→query→问题复现三步）：
  - engine-enter→prompt-sent：**60,119ms → 90ms（668 倍）**
  - step-start→prompt-sent 全链路：~61.4s → ~160ms（首次 execute 含 serve spawn +61s 一次性成本）
- **测试套件**：1124 通过；16 失败全部存量（原始代码对照复测同样失败：opencode-sdk-wrapper 6、workflow-creation 5、diagnosis-harness-regression 2、chat-context 1、NewConfigModal 1、workflow-creation-items 1 计），**零回归**
