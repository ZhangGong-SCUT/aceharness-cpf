## 解决了什么问题

### 问题

Issue #2646 诊断 run-1789539853035-b2d9facb 失败:

```
run.fail error=修复验证未过黄金标志/引擎对齐（verdict=conditional_pass），不得标 completed
```

核查发现是**格式误杀,验证质量本身合格**:

1. 修复验证实际做得很扎实:真机 6HK0125B07000225 上 release HAP 实测
   B1/B2/B3 全过、hilog+UI dump 双重取证、黄金标志(立即返回)真机达成
2. 但 agent 只在 step-conclusion **散文**里写结论(「引擎对齐:repo xxx + SDK xxx」),
   没有按 yaml prompt(419 行)要求输出 JSON 块的
   `engine_aligned: true` / `issue_golden_flag_met: true` 布尔字段
3. 引擎终审 `enforceFixVerificationGoldenFlag` 的
   `extractEngineAligned/extractIssueGoldenFlagMet` **只解析 JSON 对象**,
   散文不认 → 视为缺字段 → pass 降级 conditional_pass → run failed
4. 对照 #2721(成功):agent 输出了规范 JSON → 终审通过

另发现次要问题:信息采集把分支误判为 oh-3.35.7-release(pin 3.35.7),
agent 后续自行纠正为 3.44.9 并完成对齐(pin matched=true 未触发门禁)。

### 方案(三层)

1. **引擎散文兜底**(src/lib/state-machine/utils.ts):
   `extractIssueGoldenFlagMet` / `extractEngineAligned` 在 JSON 未找到时,
   兜底解析散文等号形式(`issue_golden_flag_met=true`),**取最后一次匹配**
   (prompt/规则回显在前、最终结论在后)。2646 的 golden_flag 字段可被救回;
   engine_aligned 连散文都没写,兜底也救不了 → 靠第 2 层
2. **技能硬性规范**(fix-strategy.md 验证要点 0b):验证结论必须输出 JSON
   块(顶层或 run_verification 嵌套)含 verdict/engine_aligned/
   issue_golden_flag_met 布尔字段;散文「引擎对齐:repo xxx」引擎不认
3. **单测防回归**(state-machine-verdict.test.ts +3):
   - 2646 形态(散文等号 true)→ pass
   - engine_aligned 完全未提及 → 仍降级
   - 结论显式 false → 降级;规则回显 false 在前、结论 true 在后 → last-wins
