## 解决了什么问题

### 问题

Issue #2721(`setPreferredOrientations` 组合方向映射错乱)诊断工作流连续 3 轮全部 failed
(run-1789476758850 / run-1789477367690 / run-1789499889101),失败原因均为:

```
run.fail error=修复验证未过黄金标志/引擎对齐（verdict=conditional_pass），不得标 completed
```

深挖发现这是**误诊链**,本机环境(真机 API 26 + ohos-sdk/26 + 5 套 flutter-sdks)完全满足验证条件:

1. issue 无版本号 → 信息采集按优先级 3 回退 dev 分支,但 step-conclusion 只在散文里写
   「- 分支 dev(branch_source=default_branch…)」,没有 JSON `"branch"` 字段
2. `extractRepoBranch()` 两个正则(JSON / `branch:` 行)都匹配不上散文 → null
3. 磁盘兜底 `readWorkspaceRepoBranch()` 只读 `repo/`(framework 仓),引擎层 Issue 的工作分支
   在 `repo-engine/` → 永远 null
4. → `ohos-flutter-sdk.json` 写入 `matched=false, reason="没有 repo 分支，无法对号入座"`
   → prompt 注入 `engine_aligned=false`,禁 pass
5. 代码修复阶段编译 flutter_embedding HAR:仓库工程 `compatibleSdkVersion="5.1.0(18)"`,
   dev 源码的 `PiPVisibilityBridge.ets` 用了 `window.getGlobalWindowMode()`(@since 20)
   → ArkTS 报 `Property does not exist` → agent **打桩**绕过(产 compile_check_only.har)
   → 按"桩产物禁止上真机"规则放弃真机验证 → conditional_pass → failed
   (实际上本机 harmony-tools/ohos-sdk/26 有该 API,真机 OpenHarmony-7.0.0.34 API 26 也支持)

### 方案(本次 26 行,与 cc14087 的 dev-alias/detached-HEAD 兜底互补)

1. `src/lib/workflow/ohos-flutter-sdk.ts` — `extractRepoBranch()` 新增中文散文正则:
   `(?:^|\n)\s*[-*]?\s*\**分支\**\s*[:：]?\s*\`?([A-Za-z0-9]...)`,匹配 step-conclusion
   实际输出格式;已验证不误报(行中「分支」、规则文档行均不命中)
2. `src/lib/state-machine/workflow-manager.ts` — `readWorkspaceRepoBranch()` 兜底读
   `repo-engine/`,引擎层 Issue 不再漏
3. `skills/cpf-ohos-issue-analysis/references/fix-strategy.md` — 新增「引擎 HAR 工程的
   API 版本对齐(禁止打桩绕过)」一节:真机 API ≥ 源码所需 API 时,把 HAR 工程
   compatibleSdkVersion 提到本机 SDK 一致(OpenHarmony 整数 / HarmonyOS "x.y.z(api)")
   用完整 SDK 重编上真机;只有真机 API 不足才允许 conditional_pass
4. `tests/ohos-flutter-sdk.test.ts` — #2721 散文格式回归测试
