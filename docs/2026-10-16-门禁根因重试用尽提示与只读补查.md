用户要求：门禁重试多次失败、预算用尽时，必须**说明原因**（来自日志核对），在**前端显示**出来，并**提醒联系门禁维护人员**。

2. **文案缺陷**：根因**未核实**（`root_cause_verified=false` / `verdict=unknown`）时，`maintainer_hint` 与重试 summary 仍可能说"不是 PR 代码问题 / 平台抖动"——未核实不能排除 PR 代码。

## 方案

### ohos-pr-gates.mjs
- `maintainer_hint` 分两级措辞：仅当 `log_platform_verified`（日志核实属 `infra_failure`/`harness_env_failure`）时才说"不是 PR 代码问题"；否则说"门禁根因未核实（日志未能定位根因，不能据此排除 PR 代码）——请携带门禁报告链接联系门禁维护人员协助排查"。
- 新增输出字段 `log_platform_verified`（= `needs_maintainer && logPlatformSide`），由后端**单一来源**决定前端措辞，前端不重复推断。
- 重试中（`need_start_build`）与 `test_failed` 两条 summary 分支同样修正：注入日志证据但未确认根因时，不再断言"平台抖动"，改说"日志核对未确认根因，按抖动预算重试但不得断言为平台抖动"。

### check-pr-gates.mjs：只读补查
- 新增 `--from-source <gate-source.json>`：从已保存的快照重放分类，**不访问 GitCode、不评论、不触发构建**；日志核对照常（对快照中引用的真实 CI 报告只读拉取）。用于给旧产物补写新字段。
- provenance：`--from-source` 时保留快照原 `checked_at`，附 `rechecked_at`/`recheck_source`/`recheck: true`；普通重跑覆盖已有产物时把旧值记入 `previous_checked_at`。补查不伪装成新一次 CI 执行。
