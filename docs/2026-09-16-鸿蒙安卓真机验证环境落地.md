# 鸿蒙+安卓真机验证环境落地（Linux 服务器）

**时间**：2026-09-15 19:30 ~ 2026-09-16 01:15
**背景**：Issue 诊断工作流（cpf-ohos-diagnosis）此前在本机跑不了运行时验证——#2492、#2721 两个 run 均因「无 HOS SDK / 无设备 / 无签名」被裁决 `conditional_pass` 落 failed（`engine_aligned=false`、`issue_golden_flag_met=false`、`run_verification.executed=false`）。本次从零搭建鸿蒙+安卓双平台复现验证能力，并把环境知识固化进 Skill，使后续 run 能拿到 `pass`。

## 问题 → 方案 → 验证

### 1. HOS SDK 缺失 → OpenHarmony 7.0（API 26）+ 工具链

- **问题**：`flutter build hap` 前置校验即退出（No Hmos SDK found）；本机无 hdc/DevEco。
- **方案**：
  - 华为云镜像下载 `command-line-tools-linux-x64-5.1.0.840.zip`（hvigor 5.18.5 / ohpm 5.1.3 / node 18 / HarmonyOS SDK）
  - OpenHarmony **7.0-Release（API 26）** SDK 组装为 `~ohos-sdk/26/{ets,js,native,previewer,toolchains}`（手机为 HarmonyOS 7.0 API 26，完全匹配）
  - 兼容性 hack：hvigor `hos-config.json` 注入 `"7.0.0":"26"` 映射；5 组件清单 metaVersion 统一 3.0.0；从 5.1.0 补 `syscap_tool`；补 `device-define/phone.json`
- **验证**：`flutter doctor` HarmonyOS toolchain ✓（`[26:default]`），`CompileArkTS` 通过（autoFillManager/isCapsLockOn 等 API 26 成员齐全）

### 2. 手机连不上 → udev 规则

- **问题**：USB 设备节点 root:root 0660，flutter 用户无权访问，`hdc list targets` 空。
- **方案**：`/etc/udev/rules.d/51-hdc.rules`（华为 VID 12d1 → MODE 0666, GROUP plugdev）+ udevadm trigger。
- **验证**：`hdc list targets` → `6HK0125B07000225`（Pura X Max，OpenHarmony-7.0.0.34 API 26）

### 3. demo 模板构建不过 → build-profile 五项改造 + ArkTS 写法修正

- **问题**：`flutter create` 生成的 HarmonyOS 模板连环报错（SDK component missing / schema 校验 / syscap 交集空 / embedding 引用 API 26 成员缺失 / handler lambda 类型错）。
- **方案**：`runtimeOS: OpenHarmony`（app+entry）+ `compatibleSdkVersion/compileSdkVersion: 26`（整数）+ `local.properties` 加 `sdk.dir` + lambda 改 class implements + `invokeMethod` 改 callback 签名。
- **验证**：`BUILD SUCCESSFUL`，`entry-default-unsigned.hap`（130M）

### 4. hap 无法签名安装 → 逆向 hvigor 密文体系

- **问题**：hvigor 只认 DevEco 密文（≥32 字符），明文被拒；无 AGC 账号无法新签。
- **方案**：逆向 `decipher-util.js`（material 三件套 PBKDF2 派生 key + AES-128-GCM，密文布局 `[4B ct+tag 长度][12B iv][ct][16B tag]`），用拷贝来的 material 把明文密码加密成 `0000001B...` 密文写入 build-profile；bundleName 对齐 Profile（`com.example.flutterabilitydemo`）。
- **验证**：`entry-default-signed.hap` 签出；**log 版系统不校验 Profile 设备绑定**，`hdc install` 成功、`aa start` 启动、Flutter 72Hz 渲染正常；**`flutter run` 全链路通**（热重载/热重启/DevTools）

### 5. 安卓侧 Gradle 卡死 → 镜像救援

- **问题**：gradle-8.14-all.zip 走国外 CDN（11KB/s，预计 5 小时）；demo Dart 用实验语法 dot-shorthands 编译失败。
- **方案**：腾讯镜像 30 秒下载 214MB 装入 dists；`.center` → 全称；顺手装 JDK 17（apt）。
- **验证**：`flutter build apk --debug` 通过（139M），AVD `cpf_android35`（emulator-5554）安装启动，App 前台运行

### 6. 引擎子进程无环境 → env-vars.yaml 注入（免重启）

- **问题**：AceHarness 引擎进程（17:31 启动）不含任何新环境变量，spawn 的 agent 拿不到 SDK。
- **方案**：写入 `~/.aceharness/data/env-vars.yaml`（8 变量含完整 PATH）。引擎每次 spawn 前重算环境指纹，检测到变化自动用新环境重启 opencode serve——**零停机**。
- **验证**：以引擎同款合并环境实测：双设备可见、hvigorw/ohpm/java 可达、hap/apk 增量构建均秒过

### 7. 环境知识未沉淀 → linux-build-env.md 三处挂载

- **问题**：新 run 的 agent 不知道本机约定，会把上述坑重踩一遍（预计浪费 2 小时/run）。
- **方案**：新增 `skills/flutter-issue-demo-reproduction/references/linux-build-env.md`（§A 环境/设备清单、§B build-profile 五项必改+签名密文块、§C ArkTS 写法约束、§D 构建安装命令、§E 报错对照表、§F 维护备忘），并在三处挂 MANDATORY 引用：
